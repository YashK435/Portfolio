Overview

What Is Time Echo?

A first-person puzzle-platformer built in Unreal Engine using C++. The core revolves around a recording system that captures the player's actions every fixed interval and replays them through a ghosted Clone Actor — cooperative problem-solving with your own past.

Players solve environmental puzzles that require buttons, pressure plates, laser hazards, and movable platforms to be engaged simultaneously — only possible by coordinating live actions with recorded ones.

The project is at a complete and polishing stage, featuring 20 handcrafted levels that progressively introduce and combine every mechanic. Built entirely in C++ with a modular, delegate-driven architecture designed for expansion.

Architecture

Key Systems

TERecordingComponent

TERecordingComponent samples frame data at fixed time intervals using elapsed time accumulation — frame-rate independent, ensuring clone playback is identical regardless of hardware.

Data is stored as an ordered array of FTEFrameData structs. On deploy, the complete array is passed to the Clone Actor. Recording window is configurable — currently capped at 10 seconds.

  • Frame-rate independent capture via time accumulation
  • ~10 second max recording window (configurable)
  • Captures position, rotation, sprint, jump, and interact flags
  • Exposes OnCloneSpawned, OnCloneInteracted, OnCloneDestroyed delegates
  • Resets cleanly on death, checkpoint reset, or level restart

ATECloneActor

ATECloneActor receives the full frame array via InitialiseWithFrames() and iterates using a repeating timer matching the original capture interval.

Transforms are applied directly via SetActorLocation — no physics simulation — for precise path replay. If the recording ends before the fixed lifetime, the clone freezes in place at its last frame.

  • Spawned at the player's recorded start position
  • Direct transform replay — no pathfinding, no physics
  • Translucent ghosted material for visual clarity
  • Fires bIsInteracting events — activates nearby buttons on playback
  • Freezes at last frame when recording is shorter than lifetime
  • Self-destructs after TotalLifetime expires

ATELaserHazard

Laser hazards are directional beams that perform two-pass detection every CheckInterval seconds. The clone blocking check always runs first — protecting the player if the clone is in position.

Clone blocking uses a custom proximity algorithm: three height sample points are tested (feet, mid-body, chest) against the beam's closest point. If any sample falls within 80 units, the laser dims to dark red.

  • Clone blocking checked before player hit detection — always
  • Three height samples per clone against beam closest point
  • 80-unit proximity threshold for block detection
  • Visual dim to dark red when clone is blocking
  • Player hit: stops recording, freezes clone, camera shake, DeathCooldown
  • Respawns at nearest active checkpoint on hit

TEInteractableBase

Buttons, pressure plates, and trigger volumes respond to both player and clone through a shared TEInteractableBase interface. Any action the player can perform, the clone can also perform during playback.

Buttons support toggle and momentary (hold-required) modes. Pressure plates deactivate when the character steps off — frozen clones can hold them indefinitely until lifetime expires.

  • Shared interface — player and clone both use identical interaction calls
  • Toggle and momentary button modes supported
  • Pressure plates — active only while character overlaps
  • Frozen clone holds plates until lifetime expires
  • Trigger volumes advance puzzle state, spawn actors, open paths

Environmental Systems

ATEDoor slides between open and closed states using VInterpTo. Doors lock their linked button during movement and support auto-close with configurable delay.

TEMovablePlatform translates between a start and end position on character overlap. Supports one-way, looping, and auto-activate modes.

ATECheckpoint and ATELevelManager handle respawn. Reset-to-Checkpoint teleports to last reached point. Restart Level returns to the level start. Both reset active recordings and freeze or destroy the active clone.

  • Doors: VInterpTo sliding, configurable speed and auto-close
  • Platforms: one-way, looping, and auto-activate modes
  • Checkpoints sorted by CheckpointIndex — only advance forward
  • Reset-to-Checkpoint and Restart Level available at any time

Roadmap

Planned Extensions

The architecture is designed for these expansions without fundamental rewrites — modular, delegate-driven, and open-ended.

⧖

Multiple Simultaneous Clones

2–3 active echoes for complex cooperative puzzles requiring layered timing and independent path planning.

⟳

Time Rewind

Rewind the player's own position independently of any active clone replays — adding a second temporal layer.

⌦

Echo Overwrite

Record a new echo that modifies or cancels an active replay mid-sequence, enabling puzzle solutions that require changing the past.

⬡

Branching Timelines

Clones that behave differently based on world state at deployment time — different doors open, different platforms raised.

◻

Object Recording

Record and replay object manipulation — carrying crates through triggers, positioning objects for puzzle activation.

◈

Narrative Layer

Environmental storytelling elements triggered by checkpoint events — a story built around the mechanic without interrupting it.

Reflection

Prototype Notes

Strengths

  • Clean C++ separation — recording, clone, hazard each fully independent
  • Frame-rate independent capture ensures accurate clone playback on all hardware
  • Shared interaction interface gives player and clone full parity with no duplication
  • FTEFrameData struct extensible without breaking existing replay logic
  • Delegate-driven communication decouples systems cleanly
  • 20-level progression systematically introduces and layers every mechanic

Current Limits

  • Single active clone per puzzle room in the base prototype
  • 10-second maximum recording window limits larger puzzle spaces
  • No narrative layer — pure mechanical prototype currently
  • Prototype-level visual polish only — no final art pass
  • No persistent save or meta-progression system
