Overview

Project Overview

Ultra Drive is an experimental racing prototype where traditional controllers are replaced by real-world physical sensors. The project explores stable, real-time communication between custom hardware and Unreal Engine — translating physical distance and motion into responsive in-game vehicle behavior.

The primary goal is not racing realism, but investigating alternative input systems, hardware-software integration, and intuitive physical interaction within a game engine. Hand movement replaces button presses. Distance becomes steering depth. Motion triggers boost.

System Pipeline

Core Interaction Loop

Hand Movement → Sensor Distance Reading → ESP8266 Processing → Serial String Output → Unreal Engine → String Filtering → Blueprint Events → Vehicle Response

Communication is intentionally string-based to prioritize transparency, rapid debugging, and ease of iteration during prototyping. Keywords like LEFT, RIGHT, LEFTDRIFT, RIGHTDRIFT, and RESET map directly to Blueprint-based vehicle inputs.

Systems

Key Systems

📡

Distance-Based Steering

Ultrasonic sensors translate hand distance into layered steering responses. 5–20cm triggers normal steering. 2–5cm triggers steering combined with braking (drift). Low-cost sensors behave like analog controls.

⚡

PIR Motion Boost Trigger

A passive infrared sensor detects player movement as a binary trigger — separating acceleration input from the ultrasonic steering system entirely, adding a distinct physical gesture to boost.

🔗

Serial COM Pipeline

ESP8266 outputs keyword strings via serial. Unreal Engine reads continuously via the Serial COM Plugin. Strings are trimmed and sanitized before keyword matching — solving the hidden newline bug discovered during development.

🎮

Three Gameplay Modes

Tutorial (free-roam, sensor learning), Endless (infinite looping track, flow mastery), and Classic (fixed track, time trial). Each mode validates a different aspect of the hardware-based control experience.

Source Code

Arduino Firmware

The ESP8266 firmware reads both ultrasonic sensors and the PIR sensor, applies distance thresholds, and outputs keyword strings via serial at 50ms intervals to avoid input spam.

arduino_ultra_drive.ino 
#define trigPin1 D2
#define echoPin1 D1
#define trigPin2 D8
#define echoPin2 D7
#define pirPin   D5

void setup() {
  Serial.begin(9600);
  pinMode(trigPin1, OUTPUT); pinMode(echoPin1, INPUT);
  pinMode(trigPin2, OUTPUT); pinMode(echoPin2, INPUT);
  pinMode(pirPin, INPUT);
}

long readDistance(int trigPin, int echoPin) {
  digitalWrite(trigPin, LOW);  delayMicroseconds(2);
  digitalWrite(trigPin, HIGH); delayMicroseconds(10);
  digitalWrite(trigPin, LOW);
  return pulseIn(echoPin, HIGH) * 0.034 / 2;
}

void loop() {
  // PIR boost / reset detection
  if (digitalRead(pirPin) == HIGH) {
    Serial.println("RESET");
    delay(50);
    return;
  }

  long distance1 = readDistance(trigPin1, echoPin1); // Left hand
  long distance2 = readDistance(trigPin2, echoPin2); // Right hand

  // Steering depth system: 5-20cm = normal, <5cm = drift
  if (distance1 > 5 && distance1 <= 20 && distance2 > 20) {
    Serial.println("LEFT");
  } else if (distance1 <= 5 && distance2 > 20) {
    Serial.println("LEFTDRIFT");
  } else if (distance2 > 5 && distance2 <= 20 && distance1 > 20) {
    Serial.println("RIGHT");
  } else if (distance2 <= 5 && distance1 > 20) {
    Serial.println("RIGHTDRIFT");
  } else {
    Serial.println("NONE");
  }

  delay(50); // Avoid serial spam
}
Reflection

Postmortem

What Went Right

  • Stable, low-latency real-time hardware-to-engine communication
  • Clear sensor-to-vehicle input mapping that players learned quickly
  • String-based pipeline made debugging transparent and fast
  • Distance thresholds successfully created analog-like feel from digital sensors

What Could Improve

  • Hardware dependency significantly limits accessibility
  • No sensitivity calibration or threshold tuning system for different hand sizes
  • Wireless implementation would remove the cable tethering constraint
  • Engine-plugin version mismatch (UE5.4 vs 5.5) required workarounds
